# 2b. The registration-drift check

`tools/registration_drift_check.py` — proposed twice, never built. Built today,
running, registered on both surfaces.

It diffs the **declared** daemon set against the **running** one and emits on
mismatch: to `/home/workspace/logs/registration_drift.log`, to a heartbeat at
`/home/workspace/logs/registration_drift_heartbeat.json`, to the `:8772` bus as
a `mesh_memory` row, and to a **GitHub issue** once a lane has been absent for
**two consecutive cycles** (one sample is a restart; two is an outage).

### Built against the two things that made this hard

**1. `pgrep` substring matching is why this was never trustworthy.**
`pgrep -f <name>` matches the daemon, the `daemon_wrapper.sh` supervising it —
whose argv *carries the daemon's own script path* — and the ad-hoc launcher
scripts under `/home/workspace/logs/`, which carry the daemon's name in their
path. A live wrapper over a dead child then reads as RUNNING, which is the
exact false green that lets a crash-loop hide.

So identity is the **resolved canonical install path**, never a substring.
Supervisors are dropped before matching. Every exclusion is **logged, not
silent** — this run excluded 27 processes and says which and why — so a real
daemon accidentally installed under `logs/` becomes a finding instead of
vanishing.

*(This was not theoretical. While testing, a `pkill -f "python.*registration_drift_check.py"`
matched its own shell's command line and killed the session. The false-positive
class is real enough to have bitten during construction.)*

**2. An alarm that writes only on failure goes quiet exactly when it dies.**
Every cycle stamps the heartbeat, the clean ones included. A check that is
silent because it is passing and a check that is silent because it is dead must
not look the same — which matters more for this file than for most, since its
silence *means* "everything is fine".

### What it found on its first real run

```
declared 46   running 45   MISSING 1   one-sided 23   undeclared 2
launcher/supervisor processes excluded (not counted as daemons): 27
```

- **MISSING 1** — `ecosystems_metadata_fetcher`, the three-month clean-exit
  above. Found on the first cycle.
- **ONE-SIDED 23** — the quiet half of this problem, and the more dangerous
  half. **21 daemons are started by `go.sh` and watched by nothing**: they die
  once and stay dead until the next reboot. Two more are watched by
  `watchdog.sh` but never started at boot. Nobody had ever compared the two
  files.
- **UNDECLARED 2** — `build_watcher_api.py` and `execution_api_service.py` are
  running and appear in neither file. If they die, nothing restarts them and
  nothing notices.

Two of its own parser bugs were found **by it reporting itself one-sided**:
`go.sh` line continuations were invisible to line-oriented regexes, and
`watchdog.sh` `pgrep` guards are patterns, not paths. Both fixed; it now reports
itself correctly registered on both surfaces.

### Coverage — the standing rule applied to itself

**LANE: the host daemon lane.** It reads `go.sh` and `watchdog.sh`, which are
the only two surfaces on this box where a user daemon may be declared.

**FRACTION: 1.00 of that lane** — 46 declared daemons, both surfaces parsed.

That fraction is honest only with its scope attached, so the run **names the
misses on every invocation** rather than implying coverage it does not have:

| not covered | why |
|---|---|
| GitHub Actions schedules | run on GitHub, not on this host |
| **the tower's scheduled tasks** | a different machine; tailnet answers, every port filtered. **This is the lane the four dark lanes live on, and this check cannot see it.** |
| crontab | not daemons — and no cron daemon runs here, so they are inert regardless (#4122) |
| `supervisord-user.conf` | platform-owned, regenerated from an env var at boot; a user daemon there does not survive a reboot, so it is out of scope by construction |

**The second row is the one that matters and it must not be skimmed.** This
check would have caught the promoter crash-loop and both tower *scheduler*
disappearances as seen from this host — but it would **not** have caught these
four lanes, because they never ran here. Claiming otherwise would be the
schema-prm error exactly: a required-looking check whose green tick covers a
fraction of what its name implies. Closing that gap needs a reachable tower or
a re-hosting decision, and neither is in this change.

It declares **itself** on both surfaces, so it is supervised by the mechanism it
audits: if it dies, the next tick of `watchdog.sh` restarts it, and its own next
scan reports the gap like any other lane.
